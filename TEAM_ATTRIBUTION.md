## What this repository does not claim

This repository does **not** claim that:

- every source file in the original team repository was written by me;
- every architecture decision was made individually by me;
- all services shown in the future AWS design were personally deployed by me;
- Git commit authorship alone fully represents contribution to the group project.

## Evidence model

The portfolio uses several types of evidence:

1. **Original team repository** - preserves the shared implementation and history.
2. **Historical implementation snapshot** - preserves the fuller working state linked by the team.
3. **MVP screenshot directory** - evidence of the working prototype/UI.
4. **Prepared test-document fixtures** - evidence of the document-processing test workflow.
5. **Final presentation** - evidence of the architecture, prototype, security, scalability, operations, and deployment-roadmap narrative defended by the team.
6. **This personal repository** - curated explanation of the project and my Group Lead role.

## Why the portfolio is a separate repository

The original project repository serves collaboration and project history. A portfolio repository serves a different audience:

- senior recruiters;
- infrastructure/backend engineers;
- AI/platform engineers;
- security reviewers;
- interviewers looking for architecture reasoning.

The personal mirror therefore prioritizes:

- architectural clarity;
- implemented-vs-proposed boundaries;
- security/privacy reasoning;
- system-design trade-offs;
- source traceability;
- explicit attribution.
